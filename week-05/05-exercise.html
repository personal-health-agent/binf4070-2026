5 · Semantic SQL: ai_filter and ai_extract


Which notes say this patient currently has a penicillin allergy? Write SQL that calls a model function. DuckDB in the browser cannot call a model from inside a query, so the page runs your query in three steps and shows each one: DuckDB selects the inputs, the page sends one request per distinct input to your OpenAI model, and DuckDB stores the answers as a table. Preview shows every step and the exact request without sending anything. Without a key, a mock gives typical answers.


ai_filter(question, input [, reason := true])  → BOOLEAN
ai_extract(instruction, input)                → STRUCT(value DOUBLE, unit VARCHAR, test_date VARCHAR, evidence VARCHAR)


Rules on this page: one model function per query, in the SELECT list; end the query with LIMIT n (or choose to run it on every row); start with CREATE OR REPLACE TABLE name AS to name the result, otherwise it is stored as last_result. Answers are cached for the session by input, so the same input is never sent twice.


Pick a question, write the SQL, press Run, then press “Check my result”. The box starts with a template that shows the two functions. The checker looks at the key columns and rows of your result, not the exact column names. Model answers vary from run to run, so where your query calls a model, the check shows a reference answer next to yours; if they differ, explain in your written answer which you think is right.













6 · Jev: a decision model


Jev answers typed questions with probabilities or labels instead of text. Paste a Jev key at the top to call it; without one, a mock shows the output format with made-up values. The same three steps apply: the rows your query selects are sent, in batches of up to 20 per request, through the course proxy to TypeSafe. The notes here are synthetic.


jev_prob(input, condition)                 → DOUBLE   (probability that the condition holds)
jev_choice(input, question, ['a', 'b', …]) → VARCHAR  (one of the options)


The DuckDB jev extension also accepts these functions in WHERE; on this page, store the probabilities first and filter them in a second query.


Pick a question, fill in the template, press Run, then press “Check my result”. As in section 5, the checker looks at the key columns and rows, and shows a reference answer next to the model’s; explain any difference in your written answer.
